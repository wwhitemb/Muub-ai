# XLS IO Mapping

## 适用范围

- 用于 `.xls` 和 `.xlsx` 工作簿的结构设计、数据整理、样式设置和交付检查。
- 适用于 MCU、SoC、IO 扩展器和其他具有引脚或接口分配的硬件系统。
- 可以接收原理图、芯片数据手册、引脚表、需求表和已有工作簿作为数据来源。
- 不负责评价原理图设计质量，不自动修改原理图，不替代电气测试，也不编造缺失的引脚、协议、电平、时序或性能参数。

## 工作流程

1. 读取并结构化源数据，先区分芯片原始复用功能、原理图网络、项目实际功能和需求表功能项。
2. 建立完整引脚清单，保留芯片定义的完整引脚范围；未能确认的字段填写“未读取”“未连接”“待确认”或“不适用”。
3. 按“主控芯片 → 接口方向 → 接口分类 → 具体功能 → 芯片引脚/IO → 原理图网络”的层级建立总览。
4. 将同一外设的多个引脚作为一个接口组管理，同时在明细表中保留每个引脚的独立记录。
5. 生成工作簿并应用功能组颜色、合并单元格、筛选、冻结窗格、换行和合理尺寸。
6. 完成交叉表核对，确认总览、引脚表、外设汇总和需求对应中的命名、IO 和颜色一致。

## 推荐工作表

- `系统IO总览`：按主控芯片、输入/输出/通信/其他接口、接口分类、具体功能、芯片引脚号、IO/复用、原理图网络和功能说明组织主视图。
- `芯片引脚表`：列出完整引脚范围，至少包含引脚号、引脚名称、类型、I/O 电平、主功能、默认复用、重定义功能、原理图网络、实际功能、需求对应和连接状态。
- `外设汇总`：按外设或接口组汇总方向、功能、引脚集合、网络和需求状态。
- `需求对应`：把需求编号或需求描述与硬件外设、功能组、IO、实现状态和备注对应起来。
- `颜色图例`：列出每个功能组的名称、颜色、含义和适用范围。

详细字段、布局和样式规则见 [`references/workbook-guidelines.md`](references/workbook-guidelines.md)。

## 分类和数据规则

- 接口方向至少区分输入、输出、双向、通信、模拟、电源/地、调试和未连接；具体项目可在不改变含义的前提下细分。
- 常见功能组包括显示数据、显示控制、模拟采样、按键/控制、CAN、UART/串口、SPI、I2C、存储、灯光/蜂鸣器、下载调试、时钟、复位和电源/地。
- 芯片复用名、原理图网络名和项目功能名必须分列保存，不能用项目功能名覆盖芯片原始定义。
- 对多引脚接口同时记录接口级汇总和逐脚明细，不能只记录接口名称而省略具体 IO。
- 需求表没有给出的协议、精度、采样率、额定电压或时序不得自行补写；应标记为“待确认”。
- `NC/未连接`、保留脚和内部节点应单独归类，避免与有效外设混淆。

## 直观显示要求

- 按实际功能组整行或整组着色，不使用没有语义的蓝白交替行。
- 同一功能组在所有工作表中使用同一颜色，并在 `颜色图例` 中明确说明；颜色表示功能分类，不表示优先级、质量或风险等级。
- 主表按接口方向、接口分类和功能组进行合并单元格或分组显示，避免重复文字影响扫描。
- 表头使用高对比度填充和白字；冻结表头，必要时冻结引脚号、功能和网络等识别列。
- 长文本启用自动换行，设置稳定的列宽和行高；开启筛选，隐藏网格线，避免合并单元格破坏筛选区域。

## 交付前检查

- 引脚编号和关键接口是否完整，是否有重复 IO 或同一 IO 被分配到互斥功能。
- 总览、引脚表、外设汇总和需求对应中的功能名称、引脚号、网络名和状态是否一致。
- 每个功能组是否有颜色图例，颜色是否跨工作表一致。
- 未确认信息是否明确标注，是否存在凭空补写的硬件事实。
- 工作表名称、表头、筛选、冻结窗格、换行、合并单元格和列宽是否可用。
- 重新打开或导入工作簿，检查公式错误、空白关键字段和渲染异常。
