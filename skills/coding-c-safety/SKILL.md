# 嵌入式 C 安全规范

## 适用范围

仅在裸机、HAL、驱动、RTOS、中断、寄存器或通信缓冲区任务中启用。命名、格式和通用注释使用 `coding-cpp-core`。

## 按需参考

在生成或审查指针/数组边界、ISR、DMA、通信缓冲区、共享状态、资源初始化或错误清理代码时，加载 `references/embedded-c-safety-checklist.md`。只做规则审阅且不需要代码骨架时不加载。

## 核心规则

### 内存与边界

- 解引用、数组访问、环形缓冲区读写和长度计算前校验对象、容量、下标和整数溢出。
- 字符串操作必须携带容量并保证终止；避免无界复制、格式化和隐式截断。
- 优先静态或明确所有权的内存；必须动态分配时检查失败，并在同一所有权边界释放。
- 不返回栈对象地址；释放后按项目约定清空句柄或指针；大对象不要无依据放在任务栈上。
- 通信布局优先使用字节数组和显式解析；只有协议和 ABI 证据充分时才使用 `packed` 结构体。

### 中断与并发

- ISR 只做清中断、保存必要数据和发出快速通知；禁止阻塞、打印、复杂计算、协议解析和非 ISR-safe API。
- ISR 与任务共享状态使用项目提供的原子、临界区或 IPC 机制；`volatile` 不能替代同步。
- 共享数据使用合适的锁或消息传递；临界区只覆盖必要的快照，不在锁内执行文件、网络、延时或 UI 操作。
- 具体优先级、中断级别和 API 以当前 BSP/RTOS 配置和接口证据为准。

### 通信与外设

- 按协议证据校验帧头、长度、DLC、字节序、校验字段和状态；不要假定所有协议都有相同校验。
- 检查外设和 OS API 返回值，区分成功、超时、部分完成和硬件错误。
- 对异常输入采用丢弃、重试、降级或告警策略；策略和次数必须来自项目需求或配置。
- 硬件寄存器和参数集中在驱动/HAL 边界，业务层不得凭经验编造地址、ID、阈值或引脚。

### 可移植性与错误路径

- 条件编译的禁用分支必须有明确的能力声明或降级行为，不能静默伪造成功。
- 明确大小端、整数宽度、符号转换和浮点精度；使用定宽类型时遵循工程现有标准。
- 错误路径要可观察、可恢复或向上传递；统一清理块只能用于项目允许的错误处理流程。
- 不用固定内存分配器、固定线程参数或固定协议参数替代项目 API。

## 交付前检查

检查本次 diff 的对象生命周期、边界、返回值、ISR 工作量、共享状态、异常恢复和平台假设；未有证据的规则标记“待项目确认”。
