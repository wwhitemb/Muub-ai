# 嵌入式 C 安全编码规范

## 适用范围
仅在裸机、HAL、驱动、RTOS、中断、寄存器或通信缓冲区等嵌入式 C 场景时启用。Qt、普通桌面 C/C++ 和纯 LVGL API 设计不自动启用本 Skill；若 LVGL 运行在嵌入式系统中，则按任务需要叠加。

## 触发场景
- 编写/修改中断服务函数、底层驱动
- 涉及指针、数组、通信缓冲区操作
- 多任务/中断共享数据读写
- 外设初始化、硬件寄存器配置
- 代码评审、死机/跑飞类BUG排查

> **与其他Skill的边界**：
> - 命名规则 → 见 `coding-naming` Skill
> - 代码风格/注释/格式 → 见 `coding-style` Skill
> - 本Skill聚焦：安全编码、容错设计、防死机、防越界

## 核心执行规范
### 1. 内存与指针安全
1. **所有指针解引用前必须做空指针判断**，禁止裸指针直接访问
2. 数组、环形缓冲区、通信帧缓存读写必须**双重校验下标上下界**，禁止越界
3. 优先使用**静态分配**（全局数组、栈变量），禁止随意使用动态内存malloc/free
4. 字符串、帧数据操作必须指定最大长度，禁止使用无边界的 `strcpy` / `sprintf`；使用有容量参数的接口，并显式保证字符串终止和返回值有效
5. 禁止对栈内存指针做 `return` 返回，防止悬垂指针
6. 结构体大小和对齐必须明确；通信帧优先使用原始字节数组和显式解析，只有经过 ABI 验证的固定布局结构体才可使用 `__attribute__((packed))`

### 2. 中断与并发安全
1. **中断服务函数仅做三件事**：标志位置位、数据浅拷贝、清中断标志；禁止阻塞、打印、复杂运算、协议解析
2. 中断与主线程共享的变量必须用 `volatile` 修饰，且读写时**关中断**或调用RT-Thread临界区接口
3. 多任务共享资源必须用**互斥锁/信号量**同步，禁止无保护并发读写全局数据池
4. 临界区代码尽可能短，禁止在临界区内调用**阻塞、延时、LVGL相关**函数
5. 禁止在中断中调用非中断安全的函数（如 `rt_malloc`、`printf`）
6. 中断优先级配置合理，通信中断优先级高于UI刷新任务

### 3. 通信与容错设计
1. 所有通信帧（CAN/RS485/一线通）必须校验**帧头、长度、校验和**，校验失败直接丢弃
2. 外设读写、通信收发必须校验**返回值**，区分正常/异常状态，禁止默认执行成功
3. 数值运算必须校验**溢出、超限**风险，车速、电压、里程等物理值做范围钳位
4. 通信异常、外设故障必须设计**重试→降级→告警**三级容错逻辑，禁止整机卡死
5. 总线故障恢复后自动重连，恢复时间可配置
6. 关键数据（里程、参数）双备份，校验失败时使用备用数据

### 4. 内存管理细则
1. 若必须使用动态内存（`aicos_malloc`），分配后**必须检查返回值是否为NULL**
2. 分配的内存必须在**同一模块内释放**，谁分配谁释放，避免跨模块所有权转移
3. 释放内存后**立即将指针置为NULL**，防止野指针二次释放
4. 通信缓冲区、协议帧缓存使用**静态环形缓冲区**，禁止运行时动态分配
5. **禁止递归调用**，防止栈溢出；任务栈大小预留30%以上冗余
6. 栈上大数组（>256字节）改为全局静态分配，避免栈溢出

### 5. 条件编译与可移植安全
1. **关键安全功能禁用条件编译裁剪**，确保默认开启，不因配置遗漏导致安全隐患
2. 条件编译的 `#else` 分支必须有降级处理逻辑，禁止留空
3. 硬件相关代码集中在Driver层，业务层、UI层**禁止直接操作寄存器**
4. 仅使用C99标准语法，禁止依赖编译器私有扩展
5. 大小端、字节序处理明确，多字节数据统一转换

### 6. 编码安全补充
1. **switch语句必须包含default分支**，处理未定义情况，防止遗漏
2. 禁止使用 `goto` 语句向前跳转，仅允许错误处理时**向后跳转到统一清理块**
3. 所有错误路径必须有明确处理，禁止静默失败
4. 浮点运算注意精度误差，比较时使用阈值而非 `==`
5. 禁止魔术数字，所有常量用宏或枚举封装
6. 数组定义时同时定义长度宏，遍历使用宏而非硬编码数字

### 7. 典型安全漏洞自查清单
| 风险类型 | 检查要点 |
|---------|---------|
| 数组越界 | 所有下标访问前是否校验范围？ |
| 空指针 | 指针解引用前是否判空？ |
| 栈溢出 | 栈上是否有大数组？是否有递归？ |
| 并发竞争 | 共享数据是否加锁/关中断保护？ |
| 内存泄漏 | 动态分配是否对称释放？ |
| 野指针 | 释放后是否置NULL？是否返回栈变量地址？ |
| 中断溢出 | ISR是否过长？是否调用了阻塞函数？ |
| 通信安全 | 帧校验是否完整？异常是否有降级处理？ |

## 输出要求
1. 风险操作必须加行内注释说明防护逻辑与边界条件
2. 涉及安全规则的代码，必须标注对应合规点
3. 存在潜在风险时，主动提示风险与替代方案
4. 交付前对照"典型安全漏洞自查清单"逐项自检
