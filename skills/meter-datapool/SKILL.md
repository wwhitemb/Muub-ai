# 仪表数据池规范

## 适用范围

仅用于本项目仪表的通信数据共享、业务结果、里程/电池/故障域和跨线程一致性。RT-Thread IPC 细节使用 `coding-rtthread-style`；持久化格式使用 `meter-storage`。

## 按需参考

新增字段、数据域、读写接口、有效性/超时逻辑或跨线程快照时，加载 `references/datapool-contract-templates.md`。只读取已有数据池接口时不加载完整模板。

## 字段契约

每个字段或数据域必须记录：

- 来源和唯一写入方；
- 类型、单位、有效范围、默认值和更新周期；
- 时间戳/序号、有效性状态、超时条件和异常保留策略；
- 读取方、是否允许业务计算覆盖以及持久化需求。

按领域拆分结构，避免把通信原始帧、业务状态和 UI 临时值混在同一无约束结构中。具体字段名、里程拆分和单位以项目接口为准。

## 读写与快照

- 模块外通过读写接口或快照接口访问，不直接暴露共享结构成员。
- 通信层只在解析成功且字段合法时写入；业务层写入计算结果；UI 只读；存储按契约读取。
- 批量相关字段必须提供原子快照，避免多次单字段读取形成混合时刻数据。
- 锁内只完成必要的复制或更新，复制到局部变量后在锁外做计算、文件、日志和 UI 操作。
- 锁、原子操作或消息传递使用工程现有机制；不在本 Skill 固定名称、优先级或实现 API。

## 有效性与超时

- 无效、过期、越界和校验失败的数据不能覆盖上一份有效值，除非项目明确要求清零。
- UI 和业务分别定义无效值的显示与计算策略；不得把无效值当作正常零值。
- 超时由接收时间戳或序号判断，恢复时重新建立有效状态并记录状态变化。
- 对关键累计量定义单调性、回绕、掉电恢复和异常回退规则；缺少需求时标记待确认。

## 数据流

```text
通信/设备 -> 解析与校验 -> 数据池 -> 业务计算/UI读取/存储快照
```

通信层不直接操作 UI，UI 不解析协议，存储不在持锁期间执行文件操作。跨层修改时同步检查调用方、并发、生命周期和错误传播。

## 交付前检查

检查字段契约、唯一写入方、原子快照、有效性/超时、锁外耗时操作、初始化默认值和异常恢复；新增字段必须配套接口和针对性验证。
