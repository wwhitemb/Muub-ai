# Figma 到 LVGL 动效实现技能

## 适用范围

仅用于把已经存在的 Figma 动画转换为 LVGL C 代码。重点处理仪表盘外圈、渐变弧、端点/扫角变化、透明度、旋转、缩放、贝塞尔缓动和 hold 时间段。

不用于重新设计 Figma 视觉稿、生成 GUI Guider 页面或替代项目已有的静态 Canvas。修改前必须读取目标 C/H 文件、创建函数、动画回调、直接调用方和相关配置，遵循最小改动原则。

## 核心目标

实现结果必须同时满足：

- 时间轴、关键帧、hold、循环方式和 easing 与 Figma 一致；
- 每条弧的物理位置、`arc[index]`、固定端、运动端、透明度方向都能明确说明；
- LVGL 操作运行在项目规定的 UI 线程中；
- 优先使用单 Canvas 和可复用绘制层，CPU、RAM 和重绘频率可解释；
- 创建失败、绘制失败、删除对象和注销动画都有可观察的错误路径；
- 高速、匀速、转向、急停等已确认模式互不改变，修正一个模式不能通过全局反转影响其他模式。

## 1. 分析顺序：先 JSON，后代码

实现前必须先分析 Figma 节点和 Motion JSON，不得只看截图或凭经验猜动画。

按以下顺序记录：

1. 读取目标节点、子节点顺序、初始属性、总时长、循环方式和 repeat delay。
2. 对每个节点列出关键时间点、几何属性、旋转、透明度、缩放、位置和 easing。
3. 将时间轴拆成独立区间，明确插值段和 hold 段；不能把多个不同 easing 的区间合并成一个近似动画。
4. 建立 Figma 到 LVGL 的角度、坐标、透明度和渐变映射，特别确认跨 0 度和正负方向。
5. 为每一段指定代码分支、渲染策略和验证点，再按时间顺序实现。

交付前必须能回答：每段起止值是什么、使用哪条曲线、哪些属性保持不变、结束画面是什么，以及哪段代码负责实现它。

### 节点和物理侧映射

不要把“内层/外层”直接当作“右侧/左侧”。先根据初始角度和画面确认物理位置，再固定映射。例如本项目当前约定：

| 物理位置 | 数组节点 | 典型初始弧段 | 说明 |
| --- | --- | --- | --- |
| 右侧圆弧 | `arc[0]` | `355° -> 55°` | 右转时可见弧，左转时淡出弧 |
| 左侧圆弧 | `arc[1]` | `175° -> 235°` | 右转时淡出弧，左转时可见弧 |

如果目标 JSON 的节点顺序不同，必须在日志中写出实际映射，不能沿用旧下标。

### 每段分析表

至少记录以下字段：

| 字段 | 需要确认的内容 |
| --- | --- |
| 时间 | 起止毫秒、是否循环边界 |
| 节点 | `arc[index]` 与物理左右侧 |
| 几何 | 起角、端角、扫角、固定端、移动端 |
| 方向 | 端点沿正方向还是负方向移动 |
| 透明度 | 节点整体 opacity、渐变头尾、是否同步变化 |
| easing | 该区间独立曲线和控制点 |
| 状态 | 区间结束时的静止/可见/隐藏结果 |

JSON 没有给出某个值时必须标记“未知”，并说明采用的项目假设，不得把推导值写成 Figma 原始值。

## 2. 方向、透明度和渐变判定

方向判断以“哪一端移动”为准，不以整张 Canvas 的旋转正负号为准：

- 先固定低透明度端；
- 让高透明度端沿 JSON 指定的正/负方向移动；
- 扫角增长表示弧段伸长，扫角减小表示收缩；
- 颜色渐变方向和透明度渐变方向分别验证，不能用改变整体旋转方向来修复颜色问题；
- 左转和右转可以镜像几何轨迹，但不能因此修改高速、匀速或急停的渐变方向。

对跨越 0 度的弧，使用连续角度表达（例如 `355° -> 55°`），在绘制前展开结束角，避免 LVGL 把负角差解释成大弧段。`start_angle == end_angle` 明确表示零长度并跳过绘制。

## 3. LVGL 渲染和性能策略

按变化属性选择实现：

1. 只有整体旋转、缩放或平移：预渲染一张 ARGB8888 Canvas，运行时使用 `lv_image_set_rotation()`、缩放或位置更新。
2. 弧端点、扫角或节点透明度变化：使用一张 Canvas，在离屏层中重合成两条弧，再提交整张 Canvas。
3. 禁止在每个动画 tick 创建/删除 Arc 对象。
4. 不要为两条弧长期创建两张大 Canvas。490x490 ARGB8888 单缓冲约 960400 字节（约 938 KiB），还不包括 LVGL 对象和绘制开销。
5. 渐变弧按固定步数绘制；仅在量化后的端角或透明度真正变化时重绘，使用角度/透明度阈值降低 CPU。
6. 量化不能改变关键帧：首帧、hold 边界、透明度 0/255 和目标角度必须强制提交。

Canvas 生命周期必须保持：分配描述符和 draw buffer → 创建并绑定 Canvas → 设置稳定尺寸、pivot 和抗锯齿 → 首帧绘制成功后启动动画 → 删除事件中先 `lv_anim_delete`，再释放 draw buffer 和描述符。

透明背景每次重绘前先清空，避免上一帧残留。不要在回调中反复绑定同一 Canvas 的图像源，也不要未经验证地删除正在显示的 draw buffer 缓存。

## 4. 时间轴实现规则

动画回调收到的值先限制到合法范围，再映射到 Figma 属性。共享时间轴的几何和透明度必须在同一个 exec callback 中更新，保证同步。

推荐的分段结构：

```c
if (elapsed < phase_ms) {
    /* 前向插值段 */
} else if (elapsed < phase_ms + hold_ms) {
    /* hold：直接写入关键帧值 */
} else {
    /* 回放插值段 */
}
```

每个插值段使用自己的 easing。`bezier(0.45, 1.45, 0.8, 1)` 必须保留过冲语义；急停 JSON 的 `mass=1, stiffness=600, damping=15` 和 `bezier(0.7,-0.4,0.4,1.4)` 不能替换成普通线性插值。hold 段必须静止，不能让 LVGL playback 在 hold 期间继续插值。

## 5. 已确认轨迹的记录格式

修改转向或急停前，先用下面格式写出轨迹；代码实现和最终回复都沿用同一份数值，避免“内层/外层”和左右侧混淆。

### 右转日志参考

```text
【右转新轨迹】
**右边圆弧：第 1 条弧 arc[0]**
低透明度端固定在 55°
初始扫角 60°：355° -> 55°
伸长扫角 90°：325° -> 55°
运动时左端沿负方向移动，右端 55° 固定

**左边圆弧：第 2 条弧 arc[1]**
低透明度端固定在 235°
初始扫角 60°：175° -> 235°
伸长扫角 90°：145° -> 235°
运动时左端沿负方向移动，右端 235° 固定

时间流程：
**0~500ms**：左右弧 60° -> 90°，同步伸长。
**500~1000ms**：保持 90°。
**1000~1500ms**：左右弧 90° -> 60°，同步收缩。
**1500~2000ms**：保持 60°。
**2000ms**：循环。
```

若 JSON 实际为转向专用的 667/666/667 ms 时间轴，应按真实 JSON 输出，不得套用上面的 500 ms 示例：

```text
【右转时间轴】
0~667ms：右侧圆弧伸长，左侧圆弧同步淡出。
667~1333ms：右侧保持最长弧，左侧保持透明。
1333~2000ms：右侧收缩，左侧收回并淡入。
2000ms：循环播放。
```

### 左转日志参考

```text
【左转新轨迹】
**左侧圆弧：第 2 条弧 arc[1]**
固定端 235°
初始：175° -> 235°，扫角 60°
伸长：145° -> 235°，扫角 90°
始终保持显示，起点沿负方向移动

**右侧圆弧：第 1 条弧 arc[0]**
固定端 50°
初始：355° -> 50°
伸长：270° -> 50°
起点沿负方向移动，透明度 100 -> 0 -> 100

时间流程：
0~667ms：左侧圆弧伸长，右侧圆弧同步淡出。
667~1333ms：左侧保持最长弧，右侧保持透明。
1333~2000ms：左侧收缩，右侧收回并淡入。
2000ms：循环播放。
```

### 急停日志参考

```text
【急停新轨迹】
**0~500ms**：弹簧动画 mass=1, stiffness=600, damping=15，长弧 1.4451 -> 短弧 1.0681（或按当前角度映射 90° -> 60°）。
**500~1000ms**：hold，保持短弧静止。
**1000~1500ms**：bezier(0.7,-0.4,0.4,1.4)，短弧 1.0681 -> 长弧 1.4451，允许先反向过冲再回弹。
**1500~2000ms**：hold，保持长弧静止。
**2000ms**：循环播放。

两条弧使用同一 Canvas 同步更新；低透明度端固定，高透明度端沿指定方向移动。
```

## 6. 修改后的状态报告要求

每次修改动画代码后，必须在回复开头输出一段醒目的状态报告，至少包含：

1. 模式名称和本次修改目标；
2. 左侧/右侧物理圆弧及 `arc[index]` 映射；
3. 每段时间的起止角、扫角、固定端、透明度和 easing；
4. 是否使用单 Canvas、是否增加重绘量或内存；
5. 构建/静态检查/运行截图的实际结果；
6. 尚未验证的硬件或显示风险。

推荐输出格式：

```text
【本次动画状态】
模式：<右转/左转/急停/高速/匀速>
目标：<一句话说明>
物理映射：右侧=<arc[index]>，左侧=<arc[index]>
时间轴：<逐段列出起止值、hold 和 easing>
方向：低透明度端固定；高透明度端沿<正/负>方向移动
渲染：单 Canvas；仅在端角/透明度量化值变化时重绘
验证：构建=<结果>；运行=<结果或未验证>；内存/CPU=<结果或未测>
风险：<未验证项；没有则写“无新增风险”>
```

日志中的数值必须来自当前代码或已分析的 JSON，不能用“应该”“大约”掩盖未确认的值。若本次只改注释，也要明确写出“动画行为未改变”。

## 7. 可见性和调试顺序

当日志显示回调执行但画面不变时，按以下顺序排查：

1. 只绘制静态首帧，确认 Canvas 可见；
2. 检查父对象、坐标、尺寸、裁剪和创建层级；
3. 用纯色、`LV_OPA_COVER` 和固定整段弧验证像素链路；
4. 再恢复渐变、透明度和动态端点；
5. 记录回调值、量化值、render 返回值和首帧 alpha；
6. 最后检查缓存、软件渲染和刷新周期。

不要把“动画回调执行”表述成“屏幕一定可见”。背景色冲突也不是首要假设，应先完成高对比静态验证。

## 8. 验证与交付

每次实现至少执行并记录：

- 工程构建和编译错误检查；
- 创建函数返回值和失败路径检查；
- 首帧静态显示验证；
- 关键时间点和完整循环验证；
- 删除父对象后动画注销、Canvas 和 draw buffer 释放验证；
- CPU、RAM、刷新频率或重绘次数的实际测量；
- 尚未验证的屏幕、GPU/软件渲染和硬件内存余量。

交付时必须给出“修改前/修改后”对比、环境标签和实际启用的 Skill。未执行的命令、未通过的测试和未测量的性能不得写成已完成。
