# Figma 到 LVGL 动效实现技能

## 适用范围

仅用于把已经存在的 Figma 动画转换为 LVGL C 代码。重点处理仪表盘外圈、渐变弧、端点/扫角变化、透明度、旋转、缩放、贝塞尔缓动和 hold 时间段。

不用于重新设计 Figma 视觉稿、生成 GUI Guider 页面或替代项目已有的静态 Canvas。修改前必须读取目标 C/H 文件、创建函数、动画回调、直接调用方和相关配置，遵循最小改动原则。

## 按需参考

转换新的 Motion JSON、修改弧段方向/透明度/easing，或需要输出逐段动画依据时，加载 `references/animation-trace-template.md`。只做静态代码审阅时不加载记录模板。

## 核心目标

实现结果必须同时满足：

- 时间轴、关键帧、hold、循环方式和 easing 与 Figma 一致；
- 每条弧的物理位置、`arc[index]`、固定端、运动端、透明度方向都能明确说明；
- LVGL 操作运行在项目规定的 UI 线程中；
- 优先使用单 Canvas 和可复用绘制层，CPU、RAM 和重绘频率可解释；
- 创建失败、绘制失败、删除对象和注销动画都有可观察的错误路径；
- 高速、匀速、转向、急停等已确认模式互不改变，修正一个模式不能通过全局反转影响其他模式。

## 1. 分析顺序：先 JSON，后代码

实现前必须先分析 Figma 节点和 Motion JSON，不得只看截图或凭经验猜动画。

按以下顺序记录：

1. 读取目标节点、子节点顺序、初始属性、总时长、循环方式和 repeat delay。
2. 对每个节点列出关键时间点、几何属性、旋转、透明度、缩放、位置和 easing。
3. 将时间轴拆成独立区间，明确插值段和 hold 段；不能把多个不同 easing 的区间合并成一个近似动画。
4. 建立 Figma 到 LVGL 的角度、坐标、透明度和渐变映射，特别确认跨 0 度和正负方向。
5. 为每一段指定代码分支、渲染策略和验证点，再按时间顺序实现。

交付前必须能回答：每段起止值是什么、使用哪条曲线、哪些属性保持不变、结束画面是什么，以及哪段代码负责实现它。

### 节点映射与分析记录

不要把“内层/外层”直接等同于物理左右。先根据初始角度、节点顺序和画面确认 `arc[index]` 映射，并记录每段的起止时间、几何端点、固定端、运动方向、透明度、easing、hold 和结束状态。JSON 未提供的值标记为“未知”，不能把推导值写成原始设计值。详细记录格式见参考文件。

## 2. 方向、透明度和渐变判定

- 方向以实际移动端点为准，不以 Canvas 旋转正负号代替判断。
- 分别验证几何方向、颜色渐变方向和透明度渐变方向；镜像轨迹不能改变其他模式的渐变语义。
- 跨越 0 度时使用连续角度并在绘制前展开结束角；起止角相等表示零长度，应跳过绘制。

## 3. LVGL 渲染和性能策略

- 仅整体变换时优先复用预渲染 Canvas；端点、扫角或透明度变化时使用稳定尺寸的单 Canvas 重绘。
- 不在动画 tick 中创建/删除对象；仅在量化值变化时重绘，关键帧、hold 边界和透明度边界必须强制提交。
- Canvas 生命周期按“资源分配 -> 创建绑定 -> 首帧成功 -> 启动动画 -> 注销动画 -> 释放资源”执行，重绘前清除透明背景。
- 内存、CPU、刷新频率和重绘次数必须按目标分辨率与工程配置实际测量，不能套用固定估算。

## 4. 时间轴实现规则

动画回调收到的值先限制到合法范围，再映射到 Figma 属性。共享时间轴的几何和透明度必须在同一个 exec callback 中更新，保证同步。

每个区间使用 JSON 指定的 easing；hold 段直接保持关键帧，不能让 playback 继续插值。动画回调先限制输入，再在同一回调中同步更新几何和透明度。遇到模式差异时保留各自曲线和物理参数，不用线性插值替代。

## 5. 验证与交付

每次实现至少执行并记录：

- 工程构建和编译错误检查；
- 创建函数返回值和失败路径检查；
- 首帧静态显示验证；
- 关键时间点和完整循环验证；
- 删除父对象后动画注销、Canvas 和 draw buffer 释放验证；
- CPU、RAM、刷新频率或重绘次数的实际测量；
- 尚未验证的屏幕、GPU/软件渲染和硬件内存余量。

画面不变时先验证静态首帧、对象层级、尺寸/裁剪和纯色像素链路，再恢复渐变与动态端点。交付时给出轨迹记录、修改前/修改后对比、环境标签、实际验证结果和未验证风险；未执行的命令、未通过的测试和未测量的性能不得写成已完成。
