# 嵌入式技术文档参考模板

本文件只在需要生成或整理嵌入式单片机技术文档正文时加载。它提供结构、证据字段和检查模板，不替代芯片手册、协议标准、目标工程规则或飞书文档 API。所有尖括号占位符都必须按实际工程证据替换；没有证据时写“待确认”或“待实测”。

## 1. 标题规范

正文最多使用四级标题。文档名称不强行编号，正文标题使用以下格式：

- 一级：`一、硬件平台`、`二、软件架构`。
- 二级：`1. 芯片与板卡`、`2. 初始化流程`，在每个一级标题内重新编号。
- 三级：`① 时钟来源`、`② 复位条件`。
- 四级：`i）输入条件`、`ii）处理步骤`、`iii）输出结果`。

不得跳级，不为装饰建立标题。没有内容的章节删除，不保留空标题。

## 2. 默认文档结构

按任务裁剪以下模板，删除不适用章节：

```markdown
# <对象>-<主题>

> 摘要：本文说明 <对象> 如何解决 <问题>，适用于 <版本或范围>。

**文档状态**：草稿 / 评审中 / 已确认 / 已归档
**适用平台**：<芯片、板卡、软件版本>
**更新时间**：YYYY-MM-DD
**标签**：<平台>、<接口或模块>、<文档类型>

## 一、平台与目标
### 1. 硬件环境
### 2. 软件环境
### 3. 目标、非目标和前置条件

## 二、原理与实现
### 1. 工作原理
### 2. 工程配置
### 3. 代码实现

## 三、验证与问题排查
### 1. 操作步骤
### 2. 预期与实际现象
### 3. 已知问题和边界

## 四、结论与维护
### 1. 结论
### 2. 待办和未决问题
### 3. 参考资料与变更记录
```

## 3. 证据和参数模板

文档开头至少区分硬件事实、软件配置、设计判断、实测结果、推测和待确认项。关键参数使用表格，并记录来源和影响：

```markdown
| 参数 | 配置值 | 单位 | 来源或计算 | 影响 | 状态 |
| --- | --- | --- | --- | --- | --- |
| <参数名> | <值或待确认> | <单位> | <手册/工程文件/实测记录> | <影响> | 已确认/待实测 |
```

针对配置或实验步骤，使用“动作 -> 参数 -> 原因 -> 预期结果”：

```markdown
#### i）<配置项>

动作：<如何配置或执行>
参数：<值、范围和单位；未知时写待确认>
依据：<工程文件、手册章节或测试记录>
预期结果：<可观察的日志、波形、寄存器或界面现象>
```

接口或协议说明至少覆盖角色、字段顺序、字节数、字节序、位域、缩放因子、有效范围、校验、超时、错误码和版本兼容性（适用时）。地址、引脚、时钟和 API 必须可追溯，不能用常见型号或经验值补全。

## 4. 按主题补充字段

只选择与当前文档相关的条目，避免把整套平台清单复制到每篇文档：

- **芯片、CubeMX 和 HAL**：完整芯片型号、封装、工具版本、HAL 包版本、时钟树、GPIO 复用、NVIC 配置和生成代码与手写代码的边界。
- **编译、下载和链接**：工具链版本、编译选项、优化等级、下载器、链接文件、Flash/RAM 使用量和可复现命令。
- **显示、存储和 DMA**：器件型号、总线宽度、时序、地址/容量、初始化顺序、Cache/MPU 属性、DMA 可访问范围和一致性验证。
- **UART、SPI、I2C、CAN、USB 等接口**：速率、帧格式、DMA/中断方式、缓冲区、分包、超时、校验和异常恢复。
- **文件系统和参数存储**：介质、挂载、分区、读写路径、掉电风险、格式化条件、版本迁移和错误码。
- **触摸、传感器和外设模块**：器件型号、地址或片选、初始化寄存器、数据换算、异常值、校准方法和证据来源。

图片按“配置界面、原理图/时序图、代码或日志、最终现象”分类；每张图片说明观察对象和重要性。外部资料记录名称、版本、章节/页码和链接；链接失效时保留标题和本地证据索引。

## 5. 架构、代码和资源说明

说明应用层、业务层、驱动/HAL、OS 适配层和硬件之间的依赖方向。新模块至少记录职责、输入、输出、依赖、初始化顺序、资源所有权和失败影响。业务层不得直接操作寄存器，硬件差异集中到驱动或适配层。

代码片段只展示能说明决策的关键部分，并注明文件和位置：

```markdown
文件：`<path>/<file>.<c|h>`，函数：`<PROJECT_API>`

前置条件：<调用线程、中断限制、初始化状态>
输入边界：<长度、枚举、范围和空指针处理>
错误路径：<返回值、日志、回滚或降级行为>
资源生命周期：<创建、持有、释放和失败清理>
```

线程、任务、中断、回调、定时器和共享缓冲区应写明触发来源、同步方式、容量、所有权、溢出策略和退出条件。代码注释说明原因、边界和失败影响；未知 API 使用占位符并标记待确认。

## 6. 测试、调试和证据记录

```markdown
| 项目 | 内容 |
| --- | --- |
| 测试环境 | <板卡、芯片、固件、工具链、供电条件> |
| 操作步骤 | <烧录、配置、输入和观测步骤> |
| 预期结果 | <协议响应、日志、波形或状态变化> |
| 实际结果 | <实测数据和证据位置> |
| 判定 | 通过 / 失败 / 部分通过 / 待确认 |
| 复现条件 | <版本、温度、电压、负载或触发概率> |
```

调试记录按“现象 -> 最小复现 -> 假设 -> 排查 -> 根因 -> 修复 -> 回归结果”组织。截图、日志和波形不能只作为装饰，必须说明观察对象和结论依据。没有实测证据的内容标记为“推测”或“待验证”。

## 7. 风险、待办和变更记录

```markdown
| 问题或风险 | 影响 | 触发条件 | 临时措施 | 负责人 | 状态 |
| --- | --- | --- | --- | --- | --- |
| <待确认内容> | <功能/安全/交付影响> | <如何出现> | <当前规避方式> | <姓名或待定> | 待确认 |
```

```markdown
- [ ] <可执行待办>（负责人：<姓名或待定>；截止：YYYY-MM-DD；交付物：<证据>）
- [x] <已完成事项>（完成：YYYY-MM-DD；证据：<日志或链接>）
```

技术决策记录决策、候选方案、选择原因、影响、验证方式、日期和决策人。文档结尾保留变更记录，注明日期、变更内容、影响范围和变更人。

## 8. 输出前检查

- [ ] 标题层级和编号正确，没有跳级或空章节。
- [ ] 已写明平台、工具链、版本、目标范围和文档依据；未知值已标记。
- [ ] 接口、协议、寄存器和时序参数有来源，适用时包含字节序、边界、校验和超时。
- [ ] 并发、内存、缓冲区、资源所有权和中断限制已说明。
- [ ] 测试包含环境、步骤、预期、实际结果、判定和证据位置。
- [ ] 事实、判断、推测和待确认项已分开；敏感信息已脱敏。
- [ ] 结论、风险、待办、参考资料和变更记录齐全。
