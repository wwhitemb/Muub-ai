# 飞书嵌入式单片机技术文档

## 触发与协作

- 用户要求创建、编写、整理或修改飞书文档，且主题涉及 MCU、RTOS、驱动、通信、存储、显示、调试或移植时使用。
- 实际创建或修改云文档时叠加 `lark-doc`；浏览知识库或已有 Wiki 时叠加 `lark-wiki`。本 Skill 负责内容结构，飞书工具 Skill 负责 API、节点和权限操作。
- 普通通知、行政文档、邮件、审批或非嵌入式内容不使用本 Skill；用户明确指定的公司模板优先于默认格式。

## 核心规则

- 默认使用简体中文，代码、命令、寄存器、协议字段和工具名称保留真实拼写。
- 不编造芯片参数、寄存器地址、引脚、时钟、协议 ID、SDK API、构建命令或测试结果。缺少证据时写“待确认”或“待实测”，并列出所需证据。
- 区分硬件事实、软件配置、设计判断、实测结果、推测和待确认项；敏感信息使用占位符或脱敏值。
- 说明架构边界、输入输出、初始化顺序、资源所有权、并发约束、错误路径和验证证据；完整工程通过仓库或附件引用，不复制无关代码。

## 按需参考

生成或整理正文时加载 `references/embedded-doc-writing.md`，只使用与当前文档类型相关的章节。该文件包含标题层级、默认结构、参数/接口、测试、风险和变更记录模板。

## 执行顺序

1. 判断文档类型、目标读者、适用平台、非目标范围和需要叠加的飞书操作 Skill。
2. 收集工程文件、手册、协议、日志、截图或波形等证据，并标注证据来源和确认状态。
3. 按参考模板建立标题和字段；配置步骤使用“动作 -> 参数 -> 原因 -> 预期结果”。
4. 只写入已确认事实；对未知 API、参数、地址、命令和结论保留占位符或待确认标记。
5. 输出结论、风险、待办、参考资料和变更记录，并执行参考文件中的检查清单。

## 适用边界

本 Skill 规范嵌入式技术文档的内容组织和排版，不替代芯片手册、SDK 规范、协议标准、代码安全规范、测试规程或飞书 API Skill。
