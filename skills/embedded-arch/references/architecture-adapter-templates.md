# 嵌入式分层与适配模板

## 加载条件

在设计模块边界、目录布局、HAL/OSAL、驱动移植、启动依赖或 GUI/业务隔离时加载。

以下结构是决策模板，不是目标工程目录。先用实际目录、构建文件和调用关系确认每层职责。

## 依赖方向

```text
应用/业务 -> 领域服务或适配层 -> 驱动/HAL -> OS/芯片
       \-> 数据池/接口契约 <- 通信、存储和 UI 适配
```

- 上层依赖下层稳定接口，下层不得反向依赖业务和 UI。
- HAL 只处理硬件动作；OS 线程、设备注册和同步机制位于驱动/适配层。
- UI 只消费整理后的状态，不直接解析协议、访问寄存器或执行文件操作。
- 跨层数据通过最小接口、快照或事件传递，不用全局变量绕过边界。

## 适配接口模板

```c
typedef struct {
    int32_t (*init)(void); /* 在线程上下文初始化；重复调用语义必须由工程定义。 */
    int32_t (*read)(uint8_t *buffer, size_t capacity, size_t *length); /* 输出缓冲区及容量；length 返回实际字节数。 */
    int32_t (*write)(const uint8_t *buffer, size_t length); /* 输入缓冲区由调用方持有；实现不得异步保存该指针。 */
    int32_t (*deinit)(void); /* 释放内部资源；之后调用应返回未初始化或等效错误。 */
} module_port_ops_t;

typedef struct {
    const module_port_ops_t *ops; /* 整个端口生命周期内有效的操作表，通常为静态存储。 */
    void *context;                /* 私有适配上下文；所有权、并发保护和生命周期由契约定义。 */
} module_port_t;
```

接口必须说明线程上下文、阻塞性、缓冲区所有权、返回值、生命周期和是否允许在 ISR 使用。阻塞型 `read/write` 不得在 ISR 调用，除非真实平台 API 明确支持。没有真实平台差异时，不为形式新增 OSAL。

## 初始化依赖模板

```text
1. 芯片/OS 基础能力
2. 设备驱动和 HAL
3. IPC、线程和文件系统
4. 通信、数据池和存储服务
5. UI/业务入口
6. 页面刷新和用户事件
```

每一步记录依赖、失败回滚和可观察错误。模块卸载时按相反顺序注销回调、停止线程、释放 IPC、关闭设备和释放内存。

## 评审清单

检查依赖方向、所有权、平台泄漏、初始化顺序、并发边界、可测试接口和生成代码边界。GUI Guider 的设计源/导出源权限使用 `guider-engineering`，不要在本文件复制其版本规则。
