# 嵌入式架构规范

## 适用范围

用于目录/模块设计、驱动移植、OSAL、GUI 适配和跨平台重构。默认只提供原则，不强制复制某个厂商目录、RTOS 宏或硬件参数。

## 按需参考

设计模块边界、适配接口、启动依赖或移植骨架时，加载 `references/architecture-adapter-templates.md`。只做局部依赖审查时不加载目录模板。

## 分层原则

推荐依赖方向：

```text
应用/业务 -> 组件或适配层 -> 驱动/HAL -> OS/芯片
```

- 上层调用下层接口，下层不得反向依赖业务或 UI。
- HAL 只放硬件操作；RTOS、设备注册和同步机制放在驱动/适配层。
- 应用层编排业务和错误策略，不直接访问寄存器、DMA 缓冲区或 GUI 生成细节。
- 跨层访问通过稳定接口或适配器；不要用全局变量绕过边界。

## 数据与模块边界

- 通信模块负责设备收发、协议解析和原始数据转换；业务模块负责计算和状态决策；UI 只消费已整理的数据。
- 持久化模块负责格式、校验、恢复和文件系统；上层通过事件或接口请求保存，不把文件操作塞入 ISR/UI 回调。
- 共享状态定义所有权、更新来源、同步方式和生命周期；跨模块只暴露最小接口。
- 模块拆分以职责、依赖和测试边界为依据，不按文件数量机械拆分。

## HAL、OSAL 与移植

- 工程已有 HAL/OSAL 时复用其接口；工程没有时不要为了形式强行新增抽象层。
- 平台差异集中在适配层、配置或构建选择中，业务代码不出现芯片私有寄存器和路径。
- 移植前列出时钟、GPIO、DMA、中断、线程、文件系统和 GUI 等依赖；每项都以当前工程证据确认。
- 初始化顺序和失败回滚由依赖关系决定；错误必须可观察，不得静默跳过关键能力。

## LVGL/Guider 边界

- LVGL 调用集中在 UI 线程或项目规定的同步边界，业务层不直接创建或修改控件。
- GUI Guider 的设计源和导出源按 `guider-engineering` 的 `project-edit`/`source-edit` 路由处理；不要在本 Skill 重复文件权限细则。

## 交付前检查

检查依赖方向、模块所有权、平台泄漏、初始化/释放顺序、并发边界和可测试接口；目录示例只能来自当前工程证据。
