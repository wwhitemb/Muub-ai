# Skill 仓库联动维护

## 触发范围

仅在目标是 Muub-ai 仓库的 Skill 维护时使用本 Skill，包括：

- 创建、修改、重命名或删除 `skills/` 下的 Skill；
- 调整 Skill 的触发条件、路由、名称、目录结构或 `references/`；
- 修改 Skill 模板、校验脚本、仓库维护文档或 CC Switch 分发规则。

普通工程开发、调用某个 Skill 完成业务代码、阅读 Skill 说明，均不触发本 Skill。Skill 内容创作仍由 `skill-creator` 负责；涉及仓库联动时同时执行本 Skill。

## 工作边界

- Muub-ai 仓库是唯一维护源。先修改仓库源文件，再考虑分发副本。
- 只有 CC Switch 的安装路径、目录结构或分发规则发生变化时，才检查或更新部署副本；普通 Skill 内容变更不直接修改部署副本。
- 不因一次 Skill 变更批量改动无关的项目规则、领域提示词或其他文档。
- 项目专属规则继续放在对应工程的 `AGENTS.md`；只有该 Skill 的路由或规则实际影响项目时才同步。
- 保持公开 Skill 名称和目录名稳定。重命名或删除前，必须完成全仓库引用检查，并记录迁移关系。

## 执行流程

### 1. 确认仓库和约束

1. 确认当前目标是 Muub-ai 仓库，定位仓库根目录和 `skills/` 目录。
2. 读取根目录及目标项目范围内的 `AGENTS.md`，再读取 `docs/skill-maintenance.md`、目标 Skill、相关模板和校验脚本。
3. 记录本次变更的 Skill 名称、旧名称（如有）、变更类型和用户要求的交付范围。

不确定目标仓库、Skill 名称或删除/重命名映射时，先停止并报告，不猜测路径或替代对象。

### 2. 建立反向引用和路由影响面

使用结构化文件读取和仓库文本搜索建立清单，至少检查：

- `skills/` 中其他 Skill 的名称、触发条件、交叉引用和必需 `references/`；
- `prompts/` 中的全局路由、领域路由和 Skill 名称；
- `project-rules/` 下的项目 `AGENTS.md`、README 和适用工程规则；
- `README.md`、`docs/`、`templates/`、`scripts/`、`CHANGELOG.md`；
- CC Switch 同步文档或明确的分发配置；
- 被改名或删除的路径、旧名称、入口链接和校验脚本中的硬编码。

影响清单必须区分三种结果：

1. 必须修改：引用、路由或校验已失效；
2. 需要人工确认：语义可能受影响，但无法由路径或名称确定；
3. 已检查无需修改：与本次变更无关，并写明判断依据。

搜索结果只用于定位对象。修改前仍需读取目标文件上下文，不得对所有同名文本做全局替换。

### 3. 按变更类型同步

#### Skill 内部规则或示例变化

- 修改目标 Skill 源文件及其直接参考文件。
- 检查反向引用、适用项目规则和 `CHANGELOG.md`。
- 仅当触发条件、名称、路径或外部行为变化时同步路由文件和 README。

#### 新增 Skill 或触发条件变化

- 确认 `SKILL.md` 的 frontmatter `name` 与目录名一致，`description` 同时说明功能和触发条件。
- 检查全局提示词、领域提示词、项目规则和 README 是否需要新增路由。
- 若存在互斥或必须搭配的 Skill，在入口文件和相关路由文档中明确加载关系。
- 若新增 `references/`，在入口中声明加载条件、版本/平台边界和互斥关系，并同步校验脚本的必需文件检查。

#### 重命名或删除 Skill

- 先搜索旧名称、目录路径和入口链接，建立旧名到新名的映射。
- 同步所有实际路由、引用、校验、文档和模板；不保留旧名称作为有效路由。
- 删除前保留可回滚的 Git 历史，并在交付报告中列出迁移结果。

#### 模板、校验或维护流程变化

- 模板字段或目录结构变化时，检查新建 Skill 的入口和现有 Skill 的兼容性。
- 校验规则变化时，更新脚本、脚本说明和受影响的验收场景。
- 不把需要人工判断的引用关系全部硬编码进脚本；脚本只检查可机械验证的存在性、格式、路径和敏感内容。

#### 分发规则变化

- 只有在 CC Switch 的仓库子目录、安装路径、Skill 目录结构或同步流程变化时，才检查部署副本和 `docs/sync-with-cc-switch.md`。
- 普通 Skill 内容变化只维护 Muub-ai 源仓库，不直接修改部署副本。

### 4. 最小化写回

- 只写入影响清单中标记为“必须修改”的文件，以及用户明确要求的文件。
- 保留现有编码、换行、frontmatter 结构和文档语言风格。
- 不重排无关章节，不批量格式化整个仓库，不修改与本次变更无关的项目规则。
- 对 Markdown 链接、Skill 名称和路径使用结构化或逐项修改；修改后再次搜索旧引用。

## 验证和交付

交付前执行与变更风险匹配的验证：

- 运行 `scripts/validate-skills.ps1`；
- 检查新 Skill 的目录名、frontmatter 名称和描述；
- 若有 `references/`，确认入口声明加载条件且必需文件存在；
- 重命名/删除时确认旧名称不再出现在有效路由和入口中；
- 校验受影响的仓库内 Markdown 链接和脚本路径；
- 重新搜索本次变更涉及的 Skill 名称、旧名称和目录路径；
- 仅在脚本或规则要求时运行其他检查，不声称执行未运行的构建或发布。

交付报告至少说明：

- 触发依据和变更类型；
- 影响清单中实际修改、已检查未修改和待人工确认的文件；
- 路由、引用、模板、校验或分发行为的变化；
- 验证命令及结果；
- 未同步的部署副本或未验证的外部发布步骤。
