# CAN/CAN FD 开发规范

## 适用范围

处理总线驱动边界和协议实现。RT-Thread 线程/IPC 使用 `coding-rtthread-style`，嵌入式边界使用 `coding-c-safety`，解析结果共享使用 `meter-datapool`。所有 ID、周期、波特率和缩放值必须来自当前项目协议。

## 按需参考

新增或修改帧解析、字节序/位域、DLC 校验、收发、过滤器、周期发送或总线故障处理代码时，加载 `references/can-frame-templates.md`。只审阅已有协议字段且不生成骨架时，可只使用本入口规则。

## 报文契约

修改或新增报文前先从协议文档、现有定义、测试帧或调用方确认：

- 标准/扩展 ID、帧类型、CAN/CAN FD、DLC/实际长度和方向；
- 字节序、起始位、位宽、符号位、缩放、偏移、单位和合法范围；
- 周期、触发条件、超时、计数器、校验字段和故障语义。

缺少证据时使用占位符并标记“待项目确认”，不得凭经验填入 ID、掩码或周期。

## 接收与解析

- 读取报文字段前先检查帧类型、DLC 和缓冲区容量；禁止越界或未对齐强转读取。
- 使用显式移位、掩码和定宽类型处理多字节字段；明确大小端和符号扩展。
- 只有协议定义了帧头、计数器、校验和或 CRC 时才校验对应字段；校验失败不得更新有效数据。
- 原始报文、解析结果和有效性状态分层保存，避免把协议解析塞入 UI 或业务层。
- 接收路径区分“未收到、长度错误、字段越界、校验失败、总线错误”等状态，并保留可观察信息。

## 收发边界

- ISR/驱动回调只完成硬件确认、必要数据转移和快速通知；解析、数据池写入和告警在任务上下文完成。
- 接收缓冲区明确所有权、覆盖策略和溢出计数；不能静默丢帧。
- 发送由单一模块负责组帧和调度；周期发送使用项目已有定时器/线程/队列机制，不复制另一套调度器。
- 检查发送返回值、邮箱/队列满、超时、bus-off 和恢复状态；失败路径不能伪造成功。

## 过滤器

- 按帧类型、ID 范围和接收方向设计最小匹配范围；标准帧和扩展帧不可混淆。
- 修改过滤掩码前确认硬件匹配规则，并用代表性 ID 做正向和反向测试。
- 过滤器未覆盖的报文应有计数或诊断入口；不要通过全接收掩盖配置错误。

## 故障与超时

- 每个需要在线状态的报文定义超时来源、有效性转换和恢复条件；具体时限以项目配置为准。
- 总线错误、控制器停止、队列溢出和连续校验失败应进入可观察的降级/告警路径。
- 恢复流程遵循驱动能力和项目状态机，不能在回调中阻塞重启或重复初始化。

## 交付前检查

确认协议证据、长度边界、字节序、校验条件、缓冲区所有权、发送失败、超时恢复和数据池接口；补充正向、短帧、非法字段、校验失败和总线异常测试。
