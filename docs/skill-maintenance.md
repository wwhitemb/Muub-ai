# Skill 维护与仓库联动

本文档适用于 Muub-ai 中 Skill、路由、参考文件、校验脚本和分发说明的维护。Muub-ai 是源仓库；Codex、Claude、CC Switch 的部署副本不是长期编辑位置。

## 职责

- `skill-creator`：定义 Skill 的职责、触发/排除条件、入口规则和按需参考文件。
- `skill-repo-maintenance`：检查反向引用、路由、目录、文档、校验和分发影响。
- 项目 `AGENTS.md`：保存项目事实和不可替代约束，不复制所有通用 Skill。

## 设计原则

1. 入口只保留触发条件、边界、决策顺序和交付检查。
2. 版本、平台和任务差异放入 `references/`，一次任务只加载必要的一份。
3. 通用规则只保留一份；其他 Skill 用链接或简短边界说明，不复制实现模板。
4. 规则必须以项目证据为准，不把硬件参数、协议 ID、线程参数和个人路径写死。
5. 已合并的兼容入口不再保留为有效 Skill；旧名称只允许出现在历史变更记录中，不能出现在路由、入口或校验逻辑中。
6. 参考文件必须是可独立按需加载的泛化模板，使用 `<MODULE>`、`<FIELD>` 等占位符，并明确要求按目标工程接口替换。

## 修改流程

### 1. 识别影响面

读取根/目标范围内的 `AGENTS.md`、目标 Skill、直接参考文件、`prompts/`、项目规则、README、`docs/` 和 `scripts/`。使用 `rg` 搜索：

- Skill 名称、目录路径和旧名称；
- 触发词、互斥关系和 `references/` 文件名；
- 路由、模板、校验脚本和分发说明。

把结果分为“必须修改、人工确认、已检查无需修改”，不要因为一个 Skill 变更批量重写无关文件。

### 2. 修改内容

- 新 Skill：目录名与 frontmatter `name` 一致，`description` 同时说明功能和触发时机。
- 路由变化：同步全局/领域提示词、项目规则、README 和实际调用方。
- 参考文件变化：入口声明加载条件、版本/平台边界和互斥关系，并确认文件存在；互斥参考不能在一次任务中全部加载。
- 兼容改名或删除：完成全仓库迁移后删除旧目录；不得出现两个同等权威的规则入口。
- 普通内容压缩：保持公开名称和行为边界，更新 `CHANGELOG.md`；不修改部署副本。

### 3. 上下文预算

- 单个 `SKILL.md` 入口建议保持在 8 KB 以内；超过 12 KB 由测量脚本警告。
- 示例只保留能改变决策的最小片段；完整模板放入按需参考文件或仓库脚本。
- 参考模板不得带入固定 CAN ID、波特率、线程参数、厂商路径、业务缩放值或项目专属宏；缺少工程证据时必须标记为未知。
- 工具读取优先 `rg` 和定向行范围；多个大文件分开读取，不重复输出已读内容。
- 使用 `scripts/measure-skill-bundles.ps1` 观察单 Skill、参考文件和典型组合的字符/行数/估算 Token。

## 校验

```powershell
.\scripts\validate-skills.ps1
.\scripts\measure-skill-bundles.ps1
git diff --check
```

`validate-skills.ps1` 负责：

- frontmatter、目录名和必需参考文件；
- 严格 UTF-8、BOM、替换字符和 NUL；
- 本地 Markdown 链接、敏感文件、绝对路径和旧 Guider 路由；
- 关键入口路由和 Guider 权限标记；
- 大文件、过多代码块和过长入口只给警告，不替代人工审查。

`measure-skill-bundles.ps1` 是容量观测工具，Token 只按字符粗略估算，不能替代实际会话统计。

## 分发

只有安装路径、Skill 目录层级或 CC Switch 扫描规则变化时才同步检查 `docs/sync-with-cc-switch.md` 和部署副本。普通内容变更只修改本仓库源文件。

## 交付报告

说明变更类型、实际修改文件、反向引用结果、路由/加载行为、校验命令及结果、未执行的部署或编译步骤。未验证的外部行为必须明确标注。
