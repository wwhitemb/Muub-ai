# Skill 维护与仓库联动

本文档是 Muub-ai Skill 源仓库的维护依据。它说明新增、修改、重命名或删除 Skill 时如何分析影响范围，以及哪些文件应根据实际引用关系同步更新。

## 适用范围与职责

本流程只针对 Muub-ai 仓库中的 Skill 源文件、路由、参考资料、模板、校验和分发文档。普通工程任务中使用既有 Skill，不触发本流程。

- `skill-creator` 负责 Skill 的内容设计、编写、拆分和重构。
- `skill-repo-maintenance` 负责仓库内的影响分析、反向引用检查、路由同步、文档同步和验证。
- 在 Muub-ai 中创建或修改 Skill 时，通常组合使用两个 Skill：先由 `skill-creator` 形成内容，再由 `skill-repo-maintenance` 检查并处理仓库联动。
- 维护 Skill 不代替领域 Skill，也不负责执行领域代码修改。
- Muub-ai 是维护目标和唯一长期源文件位置。部署到 Codex、Claude 或 CC Switch 的副本只有在分发流程发生变化时才需要检查。

## 触发条件

`skill-repo-maintenance` 仅在用户明确或任务内容明确属于以下仓库维护行为时触发：

- 新增、修改、重命名或删除 `skills/` 下的 Skill；
- 调整 Skill 的 `description`、触发条件、路由、互斥关系或加载方式；
- 增加、删除或重组 `references/`、脚本、模板、示例和其他 Skill 附件；
- 修改 Skill 校验、索引、分发规则或维护文档；
- 检查某个 Skill 变更会影响哪些提示词、项目规则、其他 Skill 或文档。

以下情况不触发本流程：

- 仅使用某个既有 Skill 完成普通代码、文档或工程任务；
- 只修改领域工程文件，且没有修改 Muub-ai 中的 Skill 或 Skill 路由；
- 只查看 Skill 内容，不要求维护仓库；
- 只部署已经验证过的 Skill，且分发规则没有变化。

## 新建 Skill

1. 复制 `templates/SKILL.md.template` 到 `skills/<skill-name>/SKILL.md`，或放入领域分组目录，例如 `skills/office/<skill-name>/SKILL.md`。
2. 将 `name` 设置为 Skill 所在目录的最后一级目录名，将 `description` 写成明确的触发条件、适用范围和排除范围；领域分组目录本身不填写为 Skill 名称。
3. 将复杂背景资料放入该 Skill 的 `references/` 目录，并在入口文件中说明每份参考文件的加载条件和互斥关系。
4. 明确该 Skill 与已有 Skill 的职责边界，避免两个入口对同一任务给出冲突规则。
5. 运行 `scripts/validate-skills.ps1`，再执行本文件的影响分析和本地链接检查。
6. 按仓库现有协作流程提交 Git；提交和推送不是触发本 Skill 的前置条件。

带有 `references/` 的 Skill 必须在入口文件中声明何时加载每份参考文件，一次任务只加载满足当前环境和任务边界的参考资料。参考文件可以按版本、平台或任务边界拆分，但不能让入口同时加载互相冲突的规范。校验脚本应检查入口和必需参考文件是否同时存在。

## 变更类型识别

开始修改前先确定变更类型。一个变更可以同时命中多个类型，但每个类型都必须有对应的影响检查。

| 变更类型 | 首要检查对象 | 可能需要同步 |
| --- | --- | --- |
| Skill 内部规则、示例或注释 | `skills/<name>/SKILL.md` 或 `skills/<domain>/<name>/SKILL.md`、`references/`、附件 | 反向引用、`CHANGELOG.md`、受影响项目规则 |
| `name`、`description`、触发条件或互斥关系 | 入口 frontmatter、全局和项目路由 | 所有名称引用、提示词、README、校验项、CHANGELOG |
| `references/` 增删、重命名或加载关系 | 入口、参考文件和校验脚本 | 入口说明、引用路径、校验脚本、相关文档 |
| 模板或示例变化 | `templates/`、使用模板的入口 | 创建流程、维护文档、校验说明 |
| 校验脚本变化 | `scripts/validate-skills.ps1` 及其文档 | 脚本说明、验收命令、CI 或分发流程（若存在） |
| Skill 重命名或删除 | 全仓库文本和路径引用 | 路由、提示词、README、项目规则、其他 Skill、CHANGELOG |
| 分发方式、安装位置或部署流程变化 | 分发脚本和 `docs/sync-with-cc-switch.md` | 架构文档、部署说明、相关校验项 |
| 仅改维护文档 | `docs/skill-maintenance.md` | 文档内链接和校验入口；不自动修改无关 Skill |

## 影响面分析

### 1. 检查 Skill 自身

检查入口文件及其直接资源，不只查看主 `SKILL.md`：

- `SKILL.md` 的 frontmatter、触发条件、排除条件和路由描述；
- `references/`、`scripts/`、`assets/`、示例和模板；
- 文件内的相对路径、Skill 名称、旧目录名和交叉引用；
- 参考文件之间的版本、平台和任务边界是否仍然互斥。

### 2. 搜索反向引用

使用 `rg` 搜索 Skill 名称、旧名称、目录路径和关键触发词，至少覆盖：

- `prompts/` 下的全局提示词和项目提示词；
- `project-rules/` 下的 `AGENTS.md`、README 和其他规则；
- `skills/` 下其他 Skill 的描述、路由、组合规则和参考文件；递归检查一级 Skill 与领域分组 Skill；
- 根 `README.md`、`CHANGELOG.md`、`docs/`、`templates/`、`scripts/`；
- 分发文档或脚本，例如 `docs/sync-with-cc-switch.md`（仅在分发关系受影响时）。

搜索结果要按“实际调用方”和“仅历史说明”区分。历史记录、示例中的旧名称不一定要改，但必须确认不会被解析为当前有效路由。

### 3. 判断同步范围

按证据决定同步文件：

- 触发条件、名称或路由变化：检查全局路由、所有实际调用方、README 和校验项；
- 参考文件结构变化：检查入口加载说明、引用路径和校验脚本；
- 规则行为变化：检查使用该规则的项目提示词、其他 Skill 组合关系和 `CHANGELOG.md`；
- 模板、验证或分发流程变化：检查对应模板、脚本、架构或分发文档；
- 仅内部措辞、示例或注释变化：通常只改 Skill 本身和 `CHANGELOG.md`，除非搜索发现调用方依赖该措辞。

不要因为新增或修改一个 Skill 就批量改写所有提示词、项目规则或文档。没有反向引用、没有行为影响的文件保持不变，并在交付报告中说明未同步无关文件的依据。

## 修改 Skill

- 先读取目标 Skill、直接引用文件和所有反向引用，再开始编辑。
- 保持公共名称、目录名和 frontmatter 结构稳定；如需改名，按“重命名或删除”流程处理全部引用。
- 规则变更时同步更新 `CHANGELOG.md`，说明变更范围和影响边界。
- 入口只描述路由和加载原则，详细语法、版本差异和领域规则放入合适的 `references/` 文件。
- 不把某个项目的硬件型号、协议 ID、私有路径或临时调试结论写入全局 Skill。
- 删除规则或文件前确认没有仍在使用的调用方，并保留可回滚的 Git 版本。

### 重命名或删除 Skill

1. 记录旧名称、目录路径和可能的别名。
2. 使用 `rg` 搜索全仓库引用，区分有效路由、文档示例和历史记录。
3. 先更新入口、调用方、README、项目规则和校验脚本，再删除旧文件或目录。
4. 再次搜索旧名称，确保没有遗漏的有效引用。
5. 在 `CHANGELOG.md` 中记录迁移方式；如部署名称也发生变化，再检查分发文档。

## 校验与验证

完成修改后按变更范围执行验证：

1. 运行 `scripts/validate-skills.ps1`，确认 frontmatter、Skill 目录、必需参考文件、敏感文件和维护文档检查通过。
2. 检查新增或修改的 Markdown 相对链接指向现有文件；链接到外部站点不要求离线访问验证。
3. 用 `rg` 搜索旧 Skill 名称、旧路径、失效参考文件名和不应继续触发的关键词。
4. 对涉及路由的变更，使用普通工程、目标工程和排除场景各做一次路由检查；确认不会因单独出现 `lvgl` 或普通代码任务误触发专用 Skill。
5. 对涉及模板、脚本或分发的变更，执行对应脚本或静态检查，并记录未能执行的外部环境步骤。
6. 运行 `git diff --check` 检查本次补丁的空白错误；它不是 Skill 触发条件，也不替代内容审查。

维护 Skill 不把每个 Skill 的完整反向引用关系硬编码到校验脚本。脚本负责机械检查，触发范围、调用方和项目影响仍由维护流程根据搜索结果人工判断。

## 交付报告

交付时至少说明：

- 变更类型、触发依据和识别到的仓库范围；
- 修改的 Skill、参考文件、模板、脚本和文档；
- 发现的实际反向引用，以及未修改无关文件的理由；
- `CHANGELOG.md`、README、项目规则或分发文档是否同步；
- 执行过的校验命令及结果；
- 未执行的验证、外部部署步骤或仍需用户确认的风险。

## 项目规则

项目专属要求放入具体工程根目录的 `AGENTS.md`，不要把硬件型号、协议 ID、目录路径和项目特殊约束写入全局规则。只有当某个 Skill 的行为实际影响该项目时，才同步项目提示词或规则；普通项目规则不因仓库新增 Skill 而自动修改。

## 常见误区

- 把 `skill-creator` 当成全仓库同步工具，遗漏反向引用检查。
- 修改了 Skill 名称却只更新目录，没有更新提示词、其他 Skill 或校验脚本。
- 新增 `references/` 后未在入口声明加载条件，导致多个版本规则同时生效。
- 看到某个领域关键词就修改所有项目提示词，没有确认实际路由关系。
- 把 CC Switch 或其他部署副本当成长期源文件，造成源仓库与部署副本的维护分叉。
- 只运行校验脚本，不检查 Markdown 本地链接、旧名称和路由排除场景。
