# 全局开发规则

本文件适用于所有编程环境，只定义通用协作约束和 Skill 路由；具体领域规则按需读取对应 Skill。

## 1. 通用规则

- 使用中文分析、沟通和代码注释；除非用户明确要求其他语言。不得批量改写既有英文注释。
- 修改前先读取目标文件、直接关联的接口、调用方和配置，遵循最小改动原则。
- 保持现有接口和项目约定，不编造硬件参数、寄存器、引脚、协议 ID、SDK API、构建命令或测试结果；缺少依据时明确标注未知并查找项目证据。
- 输入、外部数据、文件、网络和硬件边界必须校验；错误路径必须可观察，不得吞掉返回值或伪造成功。
- MCP 文件读写、高危终端命令，以及启动流程、时钟、链接脚本、寄存器、分区、删除数据等高风险操作，先说明影响并请求确认。
- 完成后报告修改文件、行为变化、验证方式、未验证风险和适用边界；修改代码时提供必要的【修改前/后】对比。
- 未实际执行的命令不得声称已执行，未实际通过的测试不得声称通过。

## 2. 环境识别

按“用户明确指定 > 项目文件/目录 > 当前 API/构建工具 > 任务语义”识别环境，可同时命中多个标签：

- `embedded_generic`：MCU、裸机、HAL、寄存器、驱动、RTOS、交叉编译或 UART/SPI/I2C/CAN 等嵌入式任务。
- `rtthread`：出现 `rtthread.h`、`rt_device`、`rt_thread`、`rt_mutex`、`INIT_APP_EXPORT` 等 RT-Thread 证据。
- `lvgl`：出现 `lvgl.h`、`lv_` API、屏幕、控件或刷新逻辑；单独命中该标签不代表 GUI Guider。
- `guider`：确认 LVGL 后，目标工程还存在 GUI Guider 的 `.guiguider`、`custom/` 或 `generated/` 等证据。
- `qt`：出现 Qt/C++、`QObject`、`QWidget`、`QQuick`、QML、signals/slots、`.pro` 或 Qt CMake 包。
- `can_meter_domain`：涉及本项目仪表 CAN、数据池、里程、故障码或参数存储。
- `xls_io_mapping`：涉及芯片、外设、接口、IO 与需求对应关系的 `.xls/.xlsx` 工作簿；普通表格任务不触发。

无法确认或证据冲突时，按现有代码和项目约定处理，并说明假设。

## 3. Skill 路由

- 所有 C/C++ 代码生成或修改：启用 `coding-cpp-core`。嵌入式 C 追加 `coding-c-safety`。
- 嵌入式架构或移植：追加 `embedded-arch`；RT-Thread：追加 `coding-rtthread-style`。
- 普通 LVGL：遵循 LVGL 线程模型和 UI/业务解耦，不自动启用 `guider-engineering`。
- GUI Guider：启用 `guider-engineering`，按版本和任务只加载一个对应参考文件；设计源修改使用 `project-edit`，导出代码、`custom/`、`generated/`、数据绑定或移植使用 `source-edit`。
- 仪表 CAN、数据池、参数/里程/故障存储：分别按任务追加 `can-bus-dev`、`meter-datapool`、`meter-storage`。
- Qt：启用 `qt-cpp-dev`；无明确跨平台证据时不启用 RT-Thread、LVGL 或 Guider Skill。
- 硬件 IO 映射：启用 `xls-io-mapping`。
- 飞书嵌入式技术文档：启用 `lark-user-skill`；实际读写文档或浏览知识库时再追加对应 `lark-doc`、`lark-wiki`。
- 修改 Muub-ai 仓库中的 Skill、路由、引用、模板、校验或分发规则：启用 `skill-repo-maintenance`；设计或编写 Skill 内容时再追加 `skill-creator`。

## 4. C/C++ 输出门槛

- 只要输出或修改 C/C++ 代码，默认启用详细注释模式；新增或修改的注释使用中文，除非用户明确指定其他注释语言。
- 详细注释模式下，每个新增或修改的函数都必须有紧邻的函数级注释；公共 API 使用完整 Doxygen，私有/静态函数说明用途、输入、输出、副作用、前提和失败处理。
- 详细注释模式下，新增或修改的宏、变量、结构体字段、枚举项、函数参数和资源句柄必须有同一行或紧邻的中文说明；新增或修改的状态赋值、资源操作、条件分支、边界校验、空指针判断、并发保护和错误路径必须说明原因、结果和失败影响。
- 用户明确要求“简洁注释”“简要注释”时，只保留一句话的函数、声明和关键风险点说明；用户明确要求“不生成注释”“省略注释”或“仅输出无注释代码”时才关闭注释。
- “只给代码”只表示省略代码块外的解释，不关闭代码内注释；无法确认的单位、范围或业务含义标注“待项目确认”，不得猜测。
- 交付前仅针对本次 diff 检查注释覆盖和语言，不批量改写未修改的历史英文注释。

## 5. 通用质量与交付

- 保持接口兼容，优先复用仓库现有模式，避免无关重构和新增依赖。
- 并发访问共享状态时使用项目已有同步机制，不跨框架混用同步 API。
- 嵌入式任务优先使用定宽整数类型，关注内存、栈、中断、并发、边界和硬件返回值。
- RT-Thread、LVGL、GUI Guider、Qt 和仪表领域任务遵循已启用 Skill 的线程、对象生命周期、分层和数据流规则。
- 交付时简要列出识别到的环境标签、实际启用的 Skill、修改内容、验证结果和未验证风险。

## 6. 上下文预算

- 只加载覆盖当前任务的最小 Skill 集；版本/平台/任务存在互斥参考时只选一份。
- 先用 `rg` 定位符号、调用方和章节，再定向读取必要行；不为查看几行代码输出完整大文件。
- 多个大文件分开读取，单次工具输出限制在当前决策所需范围；已读内容不重复输出。
- 修改后优先查看 `git diff`、`git diff --check` 和相关行，不重新读取完整文件；遇到编码异常先做严格 UTF-8 检查。
