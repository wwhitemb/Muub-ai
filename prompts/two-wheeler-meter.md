# 二轮车仪表项目全局强制规则

**项目栈**：RT-Thread + LVGL + CAN/RS485/一线通通信，车载仪表固件。
**UI流程**：GUI Guider 界面设计 -> 导出 C 代码 -> 工程适配开发。

## 核心操作约束

1. 使用中文思考和沟通，新增或修改代码时输出【修改前/后】对比。
2. MCP 读写文件、执行高危命令、修改启动/时钟/链接脚本前，必须二次确认。
3. 严禁编造寄存器地址、引脚、协议 ID 和硬件参数，存疑内容明确标注未知。
4. 修改前通读关联模块上下文，遵循最小改动原则，不破坏无关模块接口兼容性。

## 嵌入式安全红线

- 指针解引用前判空，数组和缓冲区读写校验边界。
- 中断服务函数只做必要的置位、清中断和快速处理，禁止阻塞、打印和复杂运算。
- 中断与任务共享数据必须使用项目同步机制。
- 外设操作检查返回值，报文校验帧头、长度和校验字段。
- 初始化遵循时钟使能、GPIO 配置、外设参数和中断使能顺序。
- 优先使用静态内存，通信缓冲区使用静态分配或环形队列。

## 项目约束

- UI 与业务解耦：LVGL 只做显示，数据统一从全局数据池读取。
- GUI Guider 生成代码不手工修改，自定义逻辑放在适配层。
- CAN、RS485 和一线通解析后写入数据池，UI 和业务只从数据池读取。
- 使用 `stdint.h` 定宽类型，头文件使用防重复包含保护。
- 硬件参数、协议 ID 和阈值统一配置，禁止裸魔法数字。

## 交付要求

- 优先简洁可靠，避免过度设计和无依据的接口抽象。
- 协议解析和算法函数提供典型测试用例。
- 驱动和 UI 代码说明参数范围与异常边界。
- 交付时说明实现原理、执行步骤、适用边界和验证结果。
