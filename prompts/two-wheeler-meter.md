# 二轮车仪表项目全局强制规则

**项目栈**：RT-Thread + LVGL + CAN/RS485/一线通通信，车载仪表固件。
**UI流程**：GUI Guider 界面设计 -> 导出 C 代码 -> 工程适配开发。

## 核心操作约束

1. 使用中文思考和沟通；凡是输出 C/C++ 代码，代码块内新增或修改的注释必须使用中文，不得只在代码块外解释；新增或修改代码时输出【修改前/后】对比。
2. 只要用户没有明确要求不生成注释，C/C++ 默认使用详细注释模式：宏、静态/全局/局部变量、结构体字段、枚举项、资源句柄、状态赋值、条件分支、边界校验和错误路径均须在代码附近添加中文说明；“只给代码”不关闭注释。
3. MCP 读写文件、执行高危命令、修改启动/时钟/链接脚本前，必须二次确认。
4. 严禁编造寄存器地址、引脚、协议 ID 和硬件参数，存疑内容明确标注未知。
5. 修改前通读关联模块上下文，遵循最小改动原则，不破坏无关模块接口兼容性。

## Skill 检查

编写或生成 C/C++ 代码前必须调用 `coding-naming` 和 `coding-style`；嵌入式 C 任务再调用 `coding-c-safety`，其余 Skill 按任务叠加：

| 领域 | Skill | 重点 |
| --- | --- | --- |
| 命名 | `coding-naming` | 模块、作用域、类型和语义命名 |
| 风格 | `coding-style` | 中文注释、Doxygen、格式和单一职责；代码输出前执行注释门禁 |
| 安全 | `coding-c-safety` | 指针、边界、中断、并发和帧校验 |
| RT-Thread | `coding-rtthread-style` | 任务、线程、IPC 和调度 |
| 架构 | `embedded-arch` | 分层、HAL、OSAL 和移植边界 |
| UI | `guider-engineering` | GUI Guider 1.x/2.x 版本路由、设计源和导出工程边界 |
| CAN | `can-bus-dev` | CAN 报文、解析、过滤和故障处理 |
| 数据池 | `meter-datapool` | 有效性、超时、并发和数据共享 |
| 存储 | `meter-storage` | 参数、里程、故障记录和 CRC |

## 嵌入式安全红线

- 指针解引用前判空，数组和缓冲区读写校验边界。
- 中断服务函数只做必要的置位、清中断和快速处理，禁止阻塞、打印和复杂运算。
- 中断与任务共享数据必须使用项目同步机制。
- 外设操作检查返回值，报文校验帧头、长度和校验字段。
- 初始化遵循时钟使能、GPIO 配置、外设参数和中断使能顺序。
- 优先使用静态内存，通信缓冲区使用静态分配或环形队列。

## 项目约束

- UI 与业务解耦：LVGL 只做显示，数据统一从全局数据池读取。
- GUI Guider 按任务选择路由：设计源、页面、控件和样式修改走 `project-edit`，此阶段 `generated/` 只读；导出 C/LVGL、`generated/`、`custom/` 和平台适配修改走 `source-edit`，这些目录可读写。原始工程保留 `.guiguider` 时，重新导出可能覆盖 `source-edit` 对 `generated/` 的修改。
- CAN、RS485 和一线通解析后写入数据池，UI 和业务只从数据池读取。
- 使用 `stdint.h` 定宽类型，头文件使用防重复包含保护。
- 硬件参数、协议 ID 和阈值统一配置，禁止裸魔法数字。

## 交付要求

- 优先简洁可靠，避免过度设计和无依据的接口抽象。
- 协议解析和算法函数提供典型测试用例。
- 驱动和 UI 代码说明参数范围与异常边界。
- 代码块内必须保留公共 API、回调、状态切换、资源生命周期、输入校验、边界判断、并发约束和错误路径所需的中文注释；用户要求“只给代码”时也不例外。
- 交付时说明实现原理、执行步骤、适用边界和验证结果。
